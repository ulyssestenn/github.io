# How to Start Tracking Something With Track Analysis

**Author:** Donald
**Format:** Knowledge Guide
**Status:** published
**Product:** Track Analysis
**Deck:** On the Log screen, choose the nearest event type, write what happened in ordinary language, and tap Add Event. Track Analysis timestamps the entry automatically.

Suppose you decide to keep a record of afternoon coffee for a few weeks. You do not need to design a database first.

Open Track Analysis and make the first entry.

## Choose an event type

On **Log**, select the category that best fits what happened: Food, Drink, Supplement, Activity, Sleep, Energy, Symptom, Medication, or Other.

The category is a useful broad label, not a demand that every event fit a perfect taxonomy. If none of the named types fits, use **Other**.

## Write the details in plain language

Enter enough detail to make the event intelligible later.

For example:

> Large cold brew after lunch.

or:

> 30-minute walk, easy pace.

Freeform text is the point of Track Analysis. You can preserve the detail that matters to you instead of squeezing every observation into predefined fields.

If you expect to analyze the log later, try to describe the same recurring thing in reasonably consistent language. You do not need robotic wording; you do need enough consistency that `cold brew`, `coffee`, and `caffeine drink` do not become three accidental categories unless you intended them to.

## Change the time only when you are logging later

By default, the event is timestamped when you add it.

If you are recording something that happened earlier, use **Edit Time** before saving. That keeps the history tied to when the event actually occurred rather than when you remembered to enter it.

## Tap Add Event

Tap **Add Event**. The new record appears under Recent Events on the Log screen.

If you notice a typo or wrong detail, edit the entry. If the world changed later, make a new event rather than rewriting the earlier one.

Then keep logging only the events that serve the question or record you actually care about.

## Use History once there is something to look back at

The **History** tab gives you the longer record. Keyword search becomes more useful after the log has accumulated enough entries to make memory unreliable. Track Analysis Pro also adds advanced history filters.

You can start much smaller than that. One useful event, recorded correctly, is already a functioning log.

Track Analysis records observations; it does not turn patterns in personal data into medical diagnoses or establish causation.

## Product connection
**Track Analysis.** Track Analysis stores timestamped freeform events locally on Android. Entries can be searched and edited, and Pro adds advanced filters, reusable one-tap stacks, and CSV export for analysis with a tool of the user's choice.
